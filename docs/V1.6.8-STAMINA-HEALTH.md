# V1.6.8 体力与健康系统

## 目标

把旧版本中同时承担“劳动疲劳”和“身体状况”的 `health` 拆成两个清晰状态：

- **体力 stamina**：短期劳动能力，工作消耗、休养恢复。
- **健康 health**：长期身体状况，越低死亡风险越高。

这样玩家可以明确区分“今天干不动了”和“这个人身体已经很危险”。

## 体力规则

体力范围 0—100。

- 短工、家庭副业等劳动继续沿用原劳动消耗数值，但改为扣体力。
- 实际短工日扣 0.35 体力；没有找到活的短工日仍然 0 收入、0 体力消耗。
- 口粮充足时，休养每日恢复 1.20 体力。
- 体力 ≤35 时自动停止劳动进入休养。
- 体力恢复到 ≥60 后可按原工作计划继续。
- 低体力本身不直接造成死亡。

## 健康规则

健康范围 0—100。

- 新开局人物健康为100。
- 普通休养不直接恢复健康。
- 饥饿、疾病、受伤和后续医疗/调养事件作用于健康。
- 健康低于40时记录一次身体恶化提示。

### 每日死亡概率

| 健康 | 每日死亡概率 |
| --- | ---: |
| 70—100 | 0 |
| 40—69 | 0.02% |
| 20—39 | 0.15% |
| 10—19 | 0.5% |
| 1—9 | 2% |
| 0 | 直接死亡 |

死亡判定使用存档自身的确定性随机状态，因此保存/读取不会重新创造一套完全独立的随机世界。

## 饥饿调整

V1.6.8 中，饥饿达到100不再通过 V1.2 的旧规则立刻把当前执笔人判定饿死。

缺粮仍会：

- 提高饥饿度；
- 损伤身体健康；
- 让健康逐渐进入死亡风险区间。

最终死亡由健康耗尽或低健康每日死亡判定产生。

历史版本测试仍保留旧版“饥饿100直接死亡”的行为，只有带有 `vitals.version >= 168` 的新状态使用新规则。

## 存档迁移

V1.6.7 及更早存档载入 V1.6.8 时：

1. 原 `person.health` 数值迁移到 `person.stamina`；
2. 新 `person.health` 设置为100；
3. 当前执笔人的 `resources.stamina` 与 `resources.health` 同步更新；
4. 田地、产业、婚育、历史、自动农工、母亲照看田地等其他进度保持不变。

此设计避免旧存档因为原劳动疲劳值很低而在升级后突然进入高死亡风险。

## UI

顶部资源栏同时显示：

- 体力
- 健康

家族树人物详情追加：

`体力 X / 100 · 健康 Y / 100 · 当前健康风险`

原家族树中的劳动状态条在 V1.6.8 显示体力，身体健康和死亡风险通过文字同时展示。

## 兼容层

当前引擎：`dist/engine-v168.js?v=1.6.8`

V1.6.8 在 V1.6.7 之上做包装，并对旧劳动规则进行最小兼容改造：有 `stamina` 的新状态优先用体力结算劳动；没有 `stamina` 的历史版本继续使用旧 `health` 字段，因此旧版本测试与存档语义不会被整体改写。
