# V1.5 婚育人生事件

本文件描述 V1.5 婚姻、生育与临盆事件规则。家庭经济、农业、粮市、劳动健康、自动休养、家族关系导图和历史推进继续沿用 `docs/V1.4-ECONOMY.md` 及 V1.4.2 实现。

## 设计目标

V1.5 将婚姻和生育从“玩家主动点击的工作按钮”改成随日历推进自然发生的人生事件。

核心原则：

- 务农、短工、读书、从军、休养等属于日常行动。
- 说媒、有孕、临盆属于人生经历，不占用普通行动卡。
- 婚育会改变人物、关系图、家庭人口与长期经济，因此自动暂停等待玩家决定。
- 第一版只对当前执笔人主动生成说媒和随机有孕事件，避免后期大量成年家人频繁弹窗；已出生子女仍正常进入家谱和继承系统。

## 婚姻流程

主动行动 `marry` 不再出现在 V1.5 的 `getActions()` 中，也不能通过 `selectActivity()` 启动。

未婚执笔人满足基本年龄条件后，每个自然月最多检查一次说媒机会。新游戏当月不会立刻检查，从下一个月开始自然出现机会。

当前基础月概率为 22%。拒绝过一次婚事后进入 90—180 游戏日随机冷却，冷却结束后才可能再次有人登门说亲。

候选对象会随机生成：

- 姓名与性别
- 年龄
- 家境层级
- 职业背景
- 健康
- 两项左右性格特征
- 基础能力
- 聘礼或婚仪钱物
- 媒人称呼

家境候选目前分为乡里农户、手艺人家、小商户、地方吏户旁支、旧族旁支。家庭当前声望、田产与现金提高后，可接触到更高层级候选，但仍保留低层级对象出现的可能。

事件示意：

> 王媒婆登门，说乡里农户的李氏年十九，身体尚健，性情勤俭温厚。若应下婚事，需备聘礼24钱，随后筹备十五日。

选择：

- **应下婚事**：必须有足够现金；立即支付聘礼/婚仪钱物，进入15日婚事筹备。
- **婉言谢绝**：不结婚，进入90—180日说媒冷却。

钱不够时“应下婚事”在事件界面禁用，而不是允许点击后再产生负现金。

婚事筹备不取代人物当前日常行动。只要日历正常推进，15个实际游戏日后完成婚礼。成婚时创建配偶人物，并写入双方 `spouseId`、婚姻 relation、本家 household 与关系导图。配偶继承资格仍遵守原血缘规则，不因婚姻自动取得始祖血缘继承资格。

## 怀孕流程

主动行动 `child` 不再出现在 V1.5 行动列表，也不能主动选择。

当前执笔人结婚后，每个自然月最多检查一次有孕机会。必须存在一名存活的女性配偶/执笔人作为孕妇，同时满足：

- 18—45岁
- 健康至少45
- 饥饿低于60
- 不在生产冷却期
- 当前没有另一段孕期

基础月概率按孕妇年龄变化：

| 年龄 | 基础月概率 |
|---|---:|
| 18—29 | 9% |
| 30—34 | 6% |
| 35—39 | 3% |
| 40—45 | 1% |

最终概率再根据健康、饥饿和当前战乱修正，上限12%。这不是“每月必生”，且战乱和身体状况会自然压低家庭扩张速度。

触发后时间暂停，出现“家中有孕”事件。孕期默认约270个实际推进日。

## 孕期照护

有孕事件提供三种选择：

### 静养

- 孕妇孕期临时视为休养状态。
- 不参加短工、家庭副业或家庭务农。
- 足粮时按现有休养系统恢复健康。
- 不永久改写她原来的长期工作安排，生产结束后恢复原安排。
- 生产风险降低。

### 照常生活

- 保留原工作安排。
- 不增加额外医疗支出。
- 使用正常生产风险。

### 请医者照看

- 立即支付8钱。
- 保留原工作安排。
- 明显降低生产风险。
- 钱不足时该按钮禁用。

聘礼与医者费用记录进家庭实账的“其他现金净额”，确保总账仍可核对。

## 临盆与出生

孕期倒计时到0时不会由旧 `engine.js` 直接自动生孩子，而是产生 `family-birth` 临盆事件并暂停。

在玩家处理临盆事件之前，孩子还不会加入 `people`，因此不会出现“事件还没处理，关系图里孩子已经出生”的情况。

当前结果池：

- **母子平安**：孩子正常加入家谱，母亲轻度健康损耗。
- **孩子体弱**：孩子加入家谱，但初始健康较低。
- **难产**：孩子加入家谱，母亲健康明显下降。
- **胎儿未能存活**：不创建孩子，母亲健康下降。
- **极重难产**：孩子出生，但母亲可能因难产死亡；若死者是当前执笔人，继续走原有死亡/继承系统。

生产风险根据以下变量计算：

- 孕妇年龄
- 孕妇健康
- 孕妇饥饿
- 世界战乱程度
- 孕期选择静养或请医

当前正常基础生产风险为6%，最终被限制在2%—45%的区间。35岁以上、健康较低、饥饿与高战乱会提高风险；静养和请医会降低风险。

生产结束后，存活孕妇进入360日生产冷却。出生孩子会：

- 写入父母双方 `childrenIds`
- 写入自身 `parentIds`
- 继承本家 `familyId`
- 若父母任一方属于始祖血缘，则孩子保留始祖血缘资格
- 自动出现在 V1.4.2 家族关系导图的下一代分叉线上
- 按0—5岁儿童口粮规则参与家庭消费

## 与旧存档兼容

`engine-v15.js` 在加载/创建状态时执行 `ensureFamilyLife()`：

- 为旧档补 `familyLife` 数据块。
- 若旧版人物仍有 `person.pregnancy`，迁移到 V1.5 的家庭孕期结构并清除旧字段，防止基础引擎未经临盆事件直接生育。
- 若旧档正停留在主动 `marry` 或 `child` 项目，取消该旧项目并提示重新选择日常行动；以后婚育按 V1.5 规则自然触发。
- 原有已经成婚、已经出生的配偶/子女不被重建或删除。

## 事件优先级

V1.5 不改变重大历史事件优先原则。一天推进后，如果基础引擎已经产生重大历史、农业或其他待决事件，婚育事件不会覆盖它。

如果恰好临盆到期而另一个重大事件先出现，孕期会停在到期状态；前一事件处理完后立即补发临盆事件。

普通生活消息仍按现有规则不停表；媒人说亲、有孕和临盆因为会改变人生走势而暂停。

## 主要文件

- `dist/engine-v15.js`：婚育状态、说媒、候选对象、婚事筹备、随机有孕、临盆结果与 V1.4 引擎桥接。
- `dist/v15-ui.js`：禁用钱不足的婚育事件按钮，并在人物详情显示婚事/孕期状态。
- `dist/index.html`：当前入口将基础 UI、V1.4 家计 UI 和关系图工作 UI 的引擎导入统一映射到 V1.5 facade。
- `tests/v15-family-life.test.js`：V1.5 核心婚育流程回归。

## 验证

主要验证命令：

```bash
node --test tests/*.test.js
node --check dist/engine-v15.js
node --check dist/v15-ui.js
```

测试应同时覆盖旧 V1.1—V1.4 回归，以确保婚育改造没有破坏连续时间、农业、粮市、健康、继承和家族关系图。
